API REFERENCE

Complete documentation for all five network protocols powering MangaHub — HTTP, TCP, UDP, WebSocket, and gRPC.

HTTP REST :8080
TCP Sync :9090
UDP Notify :9091
WebSocket /ws/chat
gRPC :50051
Base URL http://localhost:8080 Content-Type application/json

OVERVIEW

MangaHub uses five distinct communication protocols, each serving a specialized purpose in the system architecture.

ProtocolPortPurposeLibrary
HTTP :8080 RESTful API — user auth, manga CRUD, library management gin-gonic/gin
TCP :9090 Persistent connections for real-time progress broadcasting net (stdlib)
UDP :9091 Stateless broadcast for chapter release notifications net (stdlib)
WS :8080/ws Bidirectional real-time chat for manga discussions gorilla/websocket
gRPC :50051 Internal service communication via Protocol Buffers google.golang.org/grpc

AUTHENTICATION

MangaHub uses JWT (JSON Web Tokens) for authentication. Include the token in the Authorization header for all protected endpoints.

Header Format
HTTP Header
Authorization: Bearer <your_jwt_token>
JWT Payload
JSON
{
  "user_id": "user123",
  "username": "manga_lover",
  "exp": 1735689600
}

ERROR HANDLING

All errors return a consistent JSON body with an error message and appropriate HTTP status code.

Error Response
{
  "error": "Manga not found",
  "code": 404
}
200 OK 201 Created 400 Bad Request 401 Unauthorized 404 Not Found 500 Server Error

PUT /users/progress Update reading chapter progress ▶
Authorization
🔒 JWT Required
Request Body
FieldTypeRequiredDescription
manga_idstringrequiredManga slug ID
current_chapterintrequiredChapter number to set as current
Side Effect

Triggers a TCP broadcast to all connected clients with the updated progress data.

TCP
TCP PROGRESS SYNC
localhost:9090

Persistent TCP connections for broadcasting real-time progress updates to all connected clients. JSON messages delimited by newlines.

Connection
Shell
nc localhost 9090
MSG ProgressUpdate Broadcast reading progress to all clients ▶
Message Schema
JSON
{
  "user_id": "user123",
  "manga_id": "one-piece",
  "chapter": 1095,
  "timestamp": 1705745400
}
Behavior

Server receives the message and broadcasts it to all currently connected TCP clients. The HTTP API triggers this automatically when PUT /users/progress is called.

UDP
UDP NOTIFICATIONS
localhost:9091

Stateless UDP server for chapter release notifications. Clients register their address, then receive broadcast datagrams when new chapters are available.

MSG Register Subscribe to notifications ▶
Datagram Payload
JSON
{
  "type": "register",
  "user_id": "user123"
}
SUB ChapterRelease Incoming notification broadcast ▶
Broadcast Payload (received by client)
JSON
{
  "type": "chapter_release",
  "manga_id": "one-piece",
  "message": "Chapter 1111 of One Piece is now available!",
  "timestamp": 1705745400
}
WS
WEBSOCKET CHAT
ws://localhost:8080/ws/chat

Bidirectional WebSocket connection for real-time manga discussions. Supports join/leave events and live message broadcasting to all connected users.

Connection URL
URL
ws://localhost:8080/ws/chat?token=<jwt_token>&username=<username>
EVT message (send) Send a chat message ▶
Message Schema (client → server)
JSON
{
  "user_id": "user123",
  "username": "manga_fan",
  "message": "One Piece chapter 1111 was amazing!",
  "timestamp": 1705745400000
}
Broadcast (server → all clients)

The server broadcasts the same message JSON to all connected WebSocket clients, including the sender.

gRPC
gRPC SERVICE
localhost:50051

Internal Protocol Buffer service for efficient service-to-service communication. Used by the HTTP API to query manga data from the gRPC microservice.

Proto Definition
Protobuf
service MangaService {
  rpc GetManga(GetMangaRequest) returns (MangaResponse);
  rpc SearchManga(SearchRequest) returns (SearchResponse);
  rpc UpdateProgress(ProgressRequest) returns (ProgressResponse);
}
RPC GetManga Fetch single manga by ID ▶
Request
Protobuf
message GetMangaRequest {
  string manga_id = 1;
}
Response
Protobuf
message MangaResponse {
  string id = 1;
  string title = 2;
  string author = 3;
  repeated string genres = 4;
  string status = 5;
  int32 total_chapters = 6;
}
RPC SearchManga Search with filters via gRPC ▶
Request
Protobuf
message SearchRequest {
  string query = 1;
  string genre = 2;
  string status = 3;
  int32 limit = 4;
}
RPC UpdateProgress Sync reading progress internally ▶
Request
Protobuf
message ProgressRequest {
  string user_id = 1;
  string manga_id = 2;
  int32 chapter = 3;
  int64 timestamp = 4;
}
